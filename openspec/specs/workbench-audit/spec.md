# workbench-audit Specification

## Purpose

Обеспечить сквозную работу с блокнотами, запросами на изменение и архитектурными отчётами с проверяемым возвратом данных в общую модель.

## Requirements

### Requirement: Блокноты
Редактор SHALL принимать nbformat 4, показывать содержимое без исполнения, генерировать тематические рабочие блокноты и сохранять весь документ после выполнения.

#### Scenario: Обычный блокнот
- **WHEN** пользователь загружает ipynb, привязывает модель и запускает Jupyter
- **THEN** собственные ячейки остаются доступны, а выгруженный файл содержит сохранённые выводы

### Requirement: Управление изменениями
Мастерская SHALL фиксировать автора, цель, приоритет и приёмку запроса, связывать его с предложением и проверять ревизию при возврате пакета.

#### Scenario: Правка пакета
- **WHEN** пользователь редактирует поддерживаемый Markdown-документ архива к текущей ревизии
- **THEN** предпросмотр перечисляет изменения, а при изменившейся базе запись отклоняется

### Requirement: Функциональная приёмка
Поставка SHALL содержать реестр 40 функций и 50 улучшений и различать проверки ядра, реального браузера и ядра Python.

#### Scenario: Повторяемость
- **WHEN** инженер запускает опубликованные команды на тестовых примерах
- **THEN** получает результаты проверок без изменения рабочего JSON
