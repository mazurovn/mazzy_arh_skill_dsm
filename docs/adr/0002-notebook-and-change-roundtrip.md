# ADR 0002. Возврат вычислений Jupyter и документов OpenSpec в модель

Принято для DSM Studio 1.1. Связанные требования описаны в [спецификации рабочего места](../../openspec/specs/workbench-audit/spec.md).

## Контекст

Инженер редактирует код и Markdown в привычных инструментах. За это время другой участник может изменить каталог, связи или план релизов. Для разбора расхождения нужны идентичность исходной модели, причина правки и воспроизводимый предпросмотр.

## Решение

1. Снимок модели имеет пару project и base. Пара переносится во входную ячейку блокнота через метаданные и в манифест OpenSpec-пакета. Перед записью мастерская сверяет базу ещё раз под файловой блокировкой.
2. В блокноте есть два явных источника возврата. Ячейка dsm-input хранит исходные данные. Ячейка dsm-result публикует рассчитанную модель как JSON-вывод. Выбор источника определяет, какое изменение появится в предпросмотре. Запуск, сохранение блокнота и запись модели — три отдельных действия.
3. Обычный внешний блокнот сохраняет исходные ячейки, вложения и выводы. Привязка добавляет ячейки по краям и сохраняет заявленное Python-ядро. При отсутствии сведений о ядре у привязанного файла используется python3. Для продолжения сессии мастерская открывает отдельную копию в библиотеке проекта.
4. У запроса, предложения, требования, ADR и задачи отдельные постоянные ID. Изменяемые документы из OpenSpec ZIP сопоставляются с карточками по путям, построенным из ID активной ревизии. Возврат пакета проходит через общую проверку модели и предпросмотр. Готовность решения, задача и фактическое применение проекта видны раздельно в истории.

## Последствия

Автономный HTML может показать и подготовить документы. Выполнение Python требует локального сервера и соответствующего ядра. Графики и интерактивные выводы доступны в самом Jupyter, в автономном просмотрщике отображаются текст и перечень MIME-форматов. Для переноса на другой компьютер нужны JSON с историей архитектуры и отдельные рабочие .ipynb. Конфликт базы требует сверки с новой ревизией.

Сценарии CLI, браузера и Python перечислены в [протоколе испытаний](../audit-workbench.md).
