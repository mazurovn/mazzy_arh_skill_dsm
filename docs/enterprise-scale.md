# Приёмка DSM Studio 1.2 на каталоге предприятия

22 ноября 2026 года на Dell Inspiron 15 7000 Gaming с Intel i7-7700HQ сравнили автономные HTML версий 1.1.0 и 1.2.0 в Google Chrome 157.0.8103.38 под Linux. Данные синтетические. Генератор создаёт 1 200 объектов, 2 987 связей DSM, иерархию, связи размещения и сценарий из 180 сообщений. В 32 полных снимках меняются разные карточки. JSON занимает 18 066 849 байт. Контрольная выборка содержит 200 объектов.

## Что измерили

Числа в таблице — медиана трёх прогонов в миллисекундах. Для каждого прогона Chrome открывал новую страницу 1440 × 900. Измерение начинается при событии DOM и заканчивается после принудительного расчёта разметки и двух кадров анимации. Время открытия файла и первого отображения измерено отдельно. Лимит на тестовый процесс со всеми дочерними процессами — 768 МиБ, подкачка отключена.

В 1.1.0 полный прогон завершился системным OOM во время построения матрицы. Числа для диаграмм и истории 1.1.0 взяты из законченного прогона того же каталога с сегментом, который ограничивает только матрицу. Для измерения отдельных действий тест начинал с истории и затем открывал экраны в одинаковом порядке. В обычном HTML 1.2.0 открытие файла сразу на матрице заняло **1 125 мс**. Пик всей группы процессов во время трёх полных прогонов составил **568 МиБ**. Результаты относятся к этой машине, этому каталогу и установленному лимиту. ## Что изменилось после измерений

| Найдено в 1.1.0 | Решение и проверка в 1.2.0 |
| --- | --- |
| Матрица на 200 объектах создавала 40 000 кнопок. При выборе связи вся таблица строилась заново. | Одновременно видны до 32 строк и 32 столбцов. Оси листаются отдельно. В браузере проверены существующая связь EA-01188 → EA-01199, пустая ячейка в противоположном углу и клавиатурный переход между окнами. |
| Концептуальная схема, иерархия и кластеры выводили все 1 200 узлов сразу. | До 48 объектов на странице и закреплённые концы выбранной связи. Список граничных связей показывает второй конец и основание. Матрица и граф сохраняют выбранную пару. Порядок сценария сохраняется при перелистывании по 40 сообщений. SVG отражает текущую область. |
| Поиск по объекту повторно сравнивал целые снимки. Опрос локального сервера повторно читал документ. | Индекс по объекту учитывает оба конца ребра и редактирование основания. Для EA-01199 найдено 11 ревизий из 32. Сервер при опросе проверяет изменение файла и возвращает идентификаторы проекта и версии. |
| Расчёт кластеров перебирал пары групп, а инспектор повторно обходил зависимости. | На разреженном слое расчёт обновляет приращения только для соседних групп. На контрольной модели сохранены результаты обоих слоёв, включая 5 групп вызовов, 601 группу совместных проверок и 1 199 транзитивных потребителей последнего объекта. |
| Из каталога, требований и предложений было трудно собрать маршрут внедрения. В разных режимах скрывались разделы. | Постоянное меню и рабочий экран требования связывают запрос, разбор, предложение, ADR, релиз, работы, Apply и наблюдение. Тест проходит маршрут с пустого проекта и повторяет приёмку после расхождения. |

Модель хранит полную историю. Загрузка и разбор JSON зависят от числа версий, даже когда матрица показывает небольшую область. Автономный HTML сохраняйте через «Сохранить JSON», особенно если история превышает квоту браузера. Для работы с большим каталогом на диске подходит локальная мастерская с общим файлом для браузера и агента.

## Маршрут от потребности до фактической проверки

Начните с **«Начать изменение»** и укажите потребность, условие, ожидаемый результат, владельца и срок. В меню **«Маршрут изменения»** выберите требование. Создайте запрос, зафиксируйте решение разбора и подготовьте OpenSpec proposal. У принятого предложения запишите ADR с выбором и последствиями, создайте релиз и назначьте работы. Перед Apply мастерская покажет точный перечень правок объекта. После Apply укажите среду и фактически наблюдаемый результат установки. Запись наблюдения ведёт инженер, который проверял внедрение.

| Дополнительная возможность | Что проверить |
| --- | --- |
| 1. Очередь по этапу | В очереди выберите этап выполнения или внедрения. |
| 2. Отбор по ответственному | Выберите владельца требования и проверьте состав выборки. |
| 3. Контроль сроков | Включите «Просроченные», завершите требование и повторите отбор. |
| 4. Предшественники работ | Укажите закупку комплектующих перед установкой. Попытка завершить установку первой показывает ID открытой закупки. |
| 5. Прогноз загрузки | При вводе оценки видна загрузка до и после. В плане релиза можно перенести работу с предпросмотром обеих загрузок. |
| 6. Отклонение по приёмке | Результат «Расхождение» сохраняет свидетельство и создаёт связанную карточку. |
| 7. Повторная проверка | Новое подтверждение закрывает соответствующее отклонение той же среды и объекта. Первая проверка остаётся в истории. |
| 8. Markdown трассировки | Отчёт требования содержит решение, работы, среду и оба наблюдения. |
| 9. CSV очереди | Скачанный CSV содержит требования текущей выборки. |
| 10. Ссылка на требование | Ссылка открывает выбранную карточку в том же проекте и учитывает его идентификатор. |

Приёмочный пример проходит от требования «32 ГиБ» до замера 16 ГиБ и последующего подтверждения 32 ГиБ. Проверены перенос работы между релизами, блокировка по предшественнику, атомарный Apply, доступность меню на экране шириной 390 пикселей и открытие ссылки после выхода из раздела. [Пример с полной историей](https://github.com/mazurovn/mazzy_arh_skill_dsm/releases/download/v1.2.0/delivery-example.html).

## Как воспроизвести

Скачайте и распакуйте [большой каталог с автономной мастерской и JSON](https://github.com/mazurovn/mazzy_arh_skill_dsm/releases/download/v1.2.0/enterprise-catalog.zip). Откройте HTML и выберите «Матрица» или «Граф и схема». В истории укажите EA-01199. Для запуска тестов из репозитория нужны Node.js 22+ и Python с Playwright и Chromium.

```bash
node tests/enterprise_catalog.cjs 1200 32 /tmp/enterprise-dsm.json
python tests/enterprise_benchmark.py --html DSM-Studio.html --objects 1200 --revisions 32 --repeats 3
python tests/enterprise_benchmark.py --startup-only
python tests/delivery_browser.py
```

Переменная DSM_BROWSER позволяет выбрать установленный Chrome. Для сравнения с 1.1.0 извлеките HTML соответствующего тега через Git и передайте путь в --html. Параметр --matrix-segment 'Домен 1' измеряет ограниченную матрицу. Для повторения испытания полной матрицы 1.1.0 используйте изолированный процесс с лимитом памяти. [Исходник генератора](../tests/enterprise_catalog.cjs) · [Браузерный сценарий](../tests/delivery_browser.py).
