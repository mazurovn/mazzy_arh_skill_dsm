# Реестр функций и улучшений DSM Studio 1.1

Исходная версия — 1.0.0. Номера относятся к приёмке приложения. ID объектов Terminal Kit хранятся отдельно. В таблицах указаны действия, наблюдаемый результат и способ повторения.

## 40 новых функций

| № | Действие | Что проверить |
| --- | --- | --- |
| F01 | Открыть обычный Jupyter Notebook из файла | В автономном HTML видны порядок ячеек, код, Markdown и сохранённые выводы внешнего блокнота. |
| F02 | Вернуть вычисленную Python-модель | Выполнить ячейку с изменением model, затем dsm-result. После сохранения в предпросмотре появляется новое значение. |
| F03 | Выгрузить Python-скрипт | .py содержит код в исходном порядке. Ячейки Markdown и Raw преобразованы в комментарии. |
| F04 | Составить Markdown-отчёт по блокноту | В документ попадают текст, листинги и сохранённый вывод. Вложенные обратные кавычки сохраняются. |
| F05 | Привязать архитектурный проект к исследовательскому блокноту | До исходных ячеек появляется входная модель, после них — публикация результата. Пользовательские ячейки сохраняют ID. |
| F06 | Подготовить чистую копию .ipynb | Исходник содержит предыдущий вывод. У копии пустые outputs, сброшены счётчики, метаданные исполнения и состояние виджетов. |
| F07 | Сгенерировать блокнот приёмки требований | Профиль requirements вычисляет для каждого требования реализующие и проверяющие объекты и наличие WHEN/THEN. |
| F08 | Сгенерировать блокнот инвентаризации | Профиль placement группирует размещённые объекты по площадкам и выводит список без назначения. |
| F09 | Сгенерировать блокнот готовности релизов | Профиль readiness показывает остаток ёмкости, неизвестные оценки, задачи предложений и блокировки. |
| F10 | Работать со своим файлом в нативном Jupyter | Загрузить файл и запустить Jupyter. Его ячейки и прежний вывод видны в настоящем Notebook 7 внутри мастерской. |
| F11 | Скачать сохранённый рабочий файл Jupyter | После Ctrl+S скачивается файл с диска активной сессии со всеми ячейками и сохранёнными выводами. |
| F12 | Возобновить работу из библиотеки проекта | После перезапуска Studio открыть предыдущий блокнот и запустить копию. Ей назначается новый каталог сессии. |
| F13 | Зарегистрировать запрос на изменение | Карточка хранит инициатора, проблему, результат, критерий приёмки, приоритет, владельца и ID затронутых объектов. |
| F14 | Провести разбор запроса | Доступны принятие, отсрочка и отклонение. Сохраняются рецензент, основание и стадия. |
| F15 | Создать предложение OpenSpec из принятого запроса | Одна ревизия переводит запрос в проработку и создаёт связанное предложение с его целью и приёмкой. |
| F16 | Выгрузить описание запроса | Отдельный Markdown собирает исходную проблему, результат, решение разбора и связанные карточки. |
| F17 | Вести задачи предложения | У задачи собственный ID, родитель и исполнитель. В открытом предложении её можно завершить и вернуть в работу. |
| F18 | Проверить готовность OpenSpec-пакета | В предложении и команде spec-check видны недостающие данные требований и предупреждения по решению и задачам. |
| F19 | Посмотреть документы ZIP в редакторе | Выбрать proposal, design, tasks, спецификацию или ADR из списка путей. Текст доступен также у обычного OpenSpec ZIP. |
| F20 | Вернуть изменения Markdown из пакета DSM | Скачать ZIP, отредактировать документ или отметку задачи, загрузить ZIP, сверить изменения и применить одной ревизией. |
| F21 | Сформировать журнал за интервал версий | Между двумя выбранными ревизиями Markdown перечисляет авторов, описания, добавленные, удалённые и изменённые объекты. |
| F22 | Проследить историю конкретного запроса | В его карточке видны только ревизии, поменявшие этот запрос, с автором, описанием и затронутыми полями. |

Остальные функции находятся в разделе «Архитектура → Анализ». Команда `node dsm.cjs report PROJECT.json ИМЯ` возвращает те же строки. Для каждого из 18 отчётов тесты сверяют конкретную ожидаемую строку и пустой результат на пустой модели.

| № | Отчёт и ключ CLI | Результат анализа |
| --- | --- | --- |
| F23 | Циклы, cycles | Состав и размер каждой группы взаимно достижимых объектов в направленном графе вызовов. |
| F24 | Взаимные вызовы, reciprocal | Одна строка на пару с весом в каждом направлении. |
| F25 | Объекты без DSM-связей, isolated | ID карточек вне обоих слоёв DSM, включая карточки с отношениями других типов. |
| F26 | Вызовы с проверкой, contracts | Направленный контракт, вес и основание совместной проверки его участников. |
| F27 | Межсегментные вызовы, segments | Границы между двумя известными сегментами, откуда и куда направлен вызов. |
| F28 | Межрелизные контракты, releases | Вызовы и совместные проверки между объектами с разными назначенными релизами. |
| F29 | Число потребителей, consumers | Ранжирование по числу прямых входящих вызовов и сумме их весов. |
| F30 | Размещение, placement | Для каждого deployedOn показаны исходный объект, площадка и тип площадки. |
| F31 | Компоненты без размещения, unplaced | Сервисы и компоненты, которым ещё не назначили площадку. |
| F32 | Ответственность, owners | Инфраструктура, системы, данные, сервисы и компоненты без отношения owns и без атрибута owner. |
| F33 | Требования без проверки, verification | Требования без входящего отношения verifies. |
| F34 | Вызовы без совместной проверки, unchecked | Направленные связи без пары в слое совместных проверок, включая основание исходного вызова. |
| F35 | Решения вне предложений, decisions | Карточки ADR, для которых ни одна из сторон не указала refs между решением и предложением. |
| F36 | Единственная площадка, singleHost | Сервисы и компоненты с ровно одним объявленным deployedOn. Это инвентаризация по модели. |
| F37 | Дубли названий, duplicates | Группы ID после выравнивания регистра и пробелов, с числом объектов в каждой группе. |
| F38 | Объём бэклога, backlog | Число фич, сумма известных оценок и количество неизвестных по сегменту. |
| F39 | Резерв релиза, reserve | Ёмкость, известная нагрузка, остаток и число неизвестных оценок. Отрицательный остаток означает перегрузку. |
| F40 | Последствия блокировок, blocked | Потребители заблокированного объекта по обратным вызовам и кратчайшая глубина зависимости. |

## 50 улучшений существующих операций

| № | Изменение поведения | Контрольный пример |
| --- | --- | --- |
| U01 | Текстовый импорт распознаёт UTF-8 BOM | Загрузка файла, сохранённого с BOM, начинается с первого символа документа. |
| U02 | Блокнот принимает CRLF и source в виде массива строк | Сохранённый под Windows dsm-input даёт ту же модель. |
| U03 | Проверяется версия формата до открытия | Для nbformat 3 пользователь получает сообщение о поддержке версии 4. |
| U04 | ID ячеек проверяются с учётом версии | В 4.4 разрешены старые ячейки без ID. В 4.5 дубликат и нестроковый ID дают ошибку. |
| U05 | Ошибка содержимого указывает ячейку | Неверный source или тип тегов у второй ячейки даёт её номер в диагностике. |
| U06 | Проверяется структура сохранённых результатов | Для неверного счётчика, потока вывода, traceback или text/plain видна ошибка загрузки. |
| U07 | Проверяется назначение входной ячейки DSM | Метка dsm-input на ячейке Markdown отклоняется с объяснением. |
| U08 | Видна принадлежность блокнота | Строка состояния различает обычный документ, текущую ревизию, старую ревизию и другой проект. |
| U09 | Ограничен объём загрузки | Блокнот свыше 16 МиБ получает сообщение о пределе до открытия в редакторе. |
| U10 | Привязка учитывает исходный язык и прежнюю связь | Для Julia привязка Python недоступна. Повторное внедрение DSM отклоняется. |
| U11 | Ошибки ядра читаются в просмотрщике | У traceback видны название, сообщение и стек без управляющих ANSI-кодов оформления. |
| U12 | Богатый вывод имеет переносимое представление | Для MIME с text/plain показывается этот текст. Для HTML или графики без текста перечисляются форматы. |
| U13 | Оглавление фильтруется по типу ячеек | Отдельно выбираются Code, Markdown и Raw. |
| U14 | Поиск учитывает содержимое блока | Совпадение может находиться в исходнике, теге или сохранённом результате. |
| U15 | Можно оставить только ячейки с выводами | Фильтр сочетается с поиском и ограничением по типу. |
| U16 | Можно перетащить .ipynb на рабочую область | Файл из проводника проходит ту же проверку, что и файл из диалога. |
| U17 | Неудачное или запоздалое чтение не заменяет выбранный документ | После испорченного файла остаётся предыдущий. При параллельных загрузках учитывается последний выбор. |
| U18 | Для ячейки виден сохранённый номер исполнения | Порядок запуска различим, даже когда ячейки выполняли вне порядка в документе. |
| U19 | Список сохранений отсортирован по времени | Перед открытием копии видны имя, время последнего изменения файла и размер. |
| U20 | Можно исследовать DSM с клавиатуры | Стрелки перемещают фокус по строкам и столбцам, Home и End переходят к краям строки. Заголовки отмечают выбранную пару. |
| U21 | Разные ID дают разные пути в OpenSpec ZIP | Кодированный ID и похожее на него буквальное имя сохраняют два отдельных spec.md. |
| U22 | Готовность указывает все пропуски по требованиям | Для пустой карточки одним ответом перечисляются WHEN, THEN и описание. |
| U23 | Видна разница между ошибкой пакета и предупреждением | Отсутствующий ADR и открытые задачи видны до выгрузки рядом с предложением. |
| U24 | Встречные правки структуры ZIP проверяются до записи | Удаление файла, новый путь или изменение служебного design сообщается с именем файла. |
| U25 | Обратный импорт учитывает тип документа | В tasks.md можно отметить или снять флажок существующей задачи. Переименование строки требует правки карточки. |
| U26 | Входящий OpenSpec ZIP сверяется с проектом и ревизией | Повтор после успешного импорта отклоняется как устаревшая база. |
| U27 | Apply записывает указанного автора | Автор решения виден в очередной ревизии и истории запроса. |
| U28 | Apply сохраняет сформулированную причину | В журнале виден введённый смысл изменения, в том числе номер запроса. |
| U29 | Завершение предложения учитывает его задачи | Открытая задача блокирует завершение. В завершённом предложении кнопки изменения задач недоступны. |
| U30 | Закрытие запроса учитывает другие предложения | Если на запрос ссылаются два предложения, он закрывается после последнего. |
| U31 | Поиск объектов учитывает атрибуты, описание и ссылки | Для сервера находится ключ memoryGiB и его значение. |
| U32 | В поиске реестра можно комбинировать слова | Запрос «memoryGiB 32» выбирает только строки, где присутствуют оба слова. |
| U33 | Есть фильтр по типу карточки | В смешанном каталоге можно оставить серверы. |
| U34 | Есть фильтр по состоянию карточки | Выбор «Проверка» оставляет объекты на рецензировании. |
| U35 | Есть фильтр по сегменту | Список сегментов составляется из текущих карточек. |
| U36 | Релиз и бэклог доступны как отдельные выборки | Выбор «Без релиза» оставляет объекты с пустым назначением. |
| U37 | Настраивается сортировка каталога | Можно вернуть исходный порядок или отсортировать по названию и ID с числовыми фрагментами. |
| U38 | Каталог показывает размер выборки | Счётчик меняется вместе с фильтрами и запросом. |
| U39 | Фильтры каталога сбрасываются одним действием | После сброса доступны все строки и исходный порядок. |
| U40 | CSV реестра соответствует текущей выборке | Для объектов, DSM-связей и типизированных отношений выгружаются показанные строки. |
| U41 | Историю можно ограничить автором | В списке остаются ревизии выбранного участника. |

| U43 | Фильтр истории по объекту учитывает его связи | Изменившаяся инцидентная DSM-связь попадает в историю объекта, даже когда его карточка прежняя. |
| U44 | История фильтруется по календарному периоду | Пустая граница оставляет интервал открытым. Даты считаются в часовом поясе пользователя. |
| U45 | Можно читать версии от первой к последней | Переключатель меняет порядок, сохраняя текущий фильтр. |
| U46 | Предпросмотр показывает масштаб импорта | Над подтверждением указаны отдельные количества добавлений, правок и удалений. |
| U47 | В предпросмотре видны последствия для загрузки релизов | Сопоставляются нагрузка, ёмкость и неизвестные оценки, включая создание и удаление релиза. |
| U48 | Имя исходного файла попадает в описание импорта | При загрузке revised.zip форма предлагает причину с именем этого ZIP. |
| U49 | В импорте можно задать автора и уточнить причину | Значения из формы сохраняются в новой ревизии. |
| U50 | Пустая правка видна до записи в редакторе | При совпадении моделей в предпросмотре кнопка применения недоступна. |
