## Как повторить

Работают Node 22+ и Python с зависимостями из CI. В испытании использованы Node 26.13.1, Notebook 7.5.8, JupyterLab 4.5.11, ipykernel 7.4.0, nbformat 5.11.1 и OpenSpec 2.1.1. Для локального Chrome можно указать DSM_BROWSER. Параметр OPENSPEC_BIN принимает путь к официальному CLI.

```bash
node --test --experimental-test-coverage --test-coverage-include='skills/edit-dsm-project/scripts/src/*.js' tests/core.cjs tests/workbench.cjs
python tests/mcp_client.py
python tests/browser_notebook.py
python tests/workbench_browser.py
python tests/openspec_roundtrip.py
openspec validate --all --strict
```

Подробности последовательности установки и тестирования доступны в [workflow](../.github/workflows/verify.yml). Прошлые испытания Kimi, Qwen, Claude, Codex и Grok задокументированы в [аудите 1.0](audit-1.0.md).

## Решения по рефакторингу и дальнейшие приоритеты

- Чтение и преобразование nbformat вынесены в notebook-files.js, генерация профилей — в notebook-profiles.js, взаимодействие с редактором — в notebook-panel.js. CLI и локальный сервер используют те же проверки документа, что автономный HTML.
- Переходы запроса и предложения, подготовка описания и журнала находятся в changes.js. specifications.js строит пакет и проверяет допустимые изменения. review-panel.js выводит данные этих модулей. Запись использует общий механизм транзакций проекта.
- Отчёты и фильтры вынесены в reports.js и registers.js. Таблица отчёта, выгрузка и CLI получают строки из одного расчёта. На следующем этапе для больших каталогов стоит измерить время первого показа матрицы и фильтра истории на обезличенной модели реального размера. Полная матрица содержит N² ячеек, фильтр истории объекта сравнивает снимки.
- Загрузка произвольного .ipynb поддерживает просмотр формата 4. Запуск кода требует локальной среды с соответствующим ядром. Комплект устанавливает Python. Просмотр пакета стороннего OpenSpec поддерживает текстовые Markdown, YAML и JSON. Возврат в модель определён для собственного пакета с исходной ревизией и существующими карточками. Для многошаговых сценариев и сторонних деревьев спецификаций следующим отдельным изменением потребуется сопоставление идентификаторов и сценариев.
- История архитектурной модели и файловая библиотека блокнотов имеют разные единицы сохранения. Архив JSON или HTML содержит ревизии модели. Для переноса пользовательских ячеек, результатов и вложений между компьютерами следует скачать полный .ipynb. Форматы .py и .md предназначены для чтения и передачи кода или отчёта.

Принятые решения по ревизиям, файлам и карточкам зафиксированы в [ADR 0002](adr/0002-notebook-and-change-roundtrip.md).
